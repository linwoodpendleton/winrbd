# A frame damaged on the wire, against the real lab cluster (Ceph v20.2.5, 1 monitor, 3 OSDs), made by harness/lab/secure-tamper.sh on 2026-11-21.
# The winrbd core ran in its own network namespace behind harness/lab/secure_tamper_proxy.py, which flipped bit 0 of ONE byte of ONE direction of ONE
# connection (offset counted from the first byte of that connection's stream) and wrote down what it did; wr-rbd printed the core's events and counters.
# The image (10 MiB, layering) was written and read through secure frames (--mode secure) except in crc-s2c (--mode crc). The cephx user was a throwaway
# (created for the run and deleted at its end); no key appears here. dst= is the daemon the connection went to (10.77.0.10:3300 the monitor, 68xx an OSD).
# Per case: the relay's lines (TAMPER = the bit that was flipped; END = bytes each way per connection), the core's event and result lines, the counters.
#   osd-s2c  a bit of an OSD's read reply: WR_E_M2_SEC_TAG ("secure frame failed authentication"), the connection redialled, 8 reads resent, the data right
#   osd-c2s  a bit of the core's write: the OSD dropped the connection (WR_E_NET_CLOSED), the core redialled and resent, a clean read-back shows the pattern
#   mon-s2c  a bit of the monitor's stream after the handshake: the monitor session is refused (WR_E_M2_SEC_TAG) and a new one comes up
#   hs-s2c   a bit of the monitor's handshake (offset 120): that attempt fails, the next one succeeds
#   crc-s2c  the same flip as osd-s2c in crc mode: WR_E_M2_FRAME_CRC, the same recovery
# In every case "result verify ok=1 diffs=0": the bytes the core delivered are the bytes that were written.
