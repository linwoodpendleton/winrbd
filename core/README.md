# core/

The portable C core: Ceph wire protocol (monitor client, cephx, msgr2, later OSDMap, CRUSH, OSD object I/O) and RBD format-2 image access. No platform dependencies: sockets and time are data flowing through a pump API, memory is handed over once, and the only calls from the core into a host are `random` and `log`.

License: MIT (see `COPYING.MIT`); every file starts with `/* SPDX-License-Identifier: MIT */`. Exception: `core/crush_ln/` is reserved for the LGPL-licensed CRUSH log tables (`COPYING.LGPL-2.1`); that directory does not exist yet and is not part of Phase 1 milestones 1 to 3. Nothing here is copied from Ceph, iPXE, WNBD or the Linux kernel: it is written from the spec notes in `docs/spec/`.

## Status

**Phase 1, milestones 1 to 3 are implemented and tested; milestone 4 is only the receiving half.**

| Milestone (docs/ROADMAP.md) | State |
|---|---|
| 1. Host shim interface, Linux implementation | done: `wr_host.h`, the pump API (`wr_client.h`), `harness/host/` |
| 2. Monitor over msgr2 (banner, hello, frames, CRC-32C) | done, crc mode, revision 1 |
| 3. cephx, tickets for the monitor and OSD services, renewal | done: both key types (`aes`, `aes256k`), monitor handshake, the OSD service ticket and the authorizer machinery that uses it, in-session renewal |
| 4. OSDMap | only the monitor's `MMonMap` and `MOSDMap` messages are received and handed to the consumer as raw bytes; no decoding of maps |
| 5 and later (CRUSH, OSD sessions, RBD, secure mode) | not started; `docs/design/core-architecture.md` section 10 records the hooks |

What a host gets today: create a client from a `wr_config`, a cluster description (monitor addresses, user name, key) and two memory regions; drive it with `wr_client_run()`; move bytes with `wr_conn_*`; read events and raw map messages. The client logs in to a monitor (hunting across the monitor list, backing off, re-authenticating after a lost session), keeps the session alive, renews its tickets before they expire and subscribes to `monmap` and `osdmap`. All of it is exercised against a simulated monitor and the committed vectors and public captures; `harness/host/tools/wr-monprobe` is the tool that points the same code at a real cluster (the lab Ceph v20.2.5 in `harness/lab/`).

## Layout

```
core/
  include/winrbd/       the PUBLIC headers: all a host includes (winrbd.h is the umbrella)
  src/<module>/         the implementation; wri_*.h are internal interfaces between modules
  sources.txt           the list of C files, generated by tools/gen_sources.sh (iPXE make and msbuild read it)
  tools/                gen_sources.sh (regenerate or --check the list), gen_crc32c_tab.py (the CRC table)
```

Module map, in dependency order (`util < crypto < denc < { msgr2, auth } < mon < client`):

| Directory | What it does | Tests (ctest names) |
|---|---|---|
| `src/util/` | bounds-checked cursors, bump arena, index pool, byte ring, overflow-safe arithmetic, base64, constant-time compare, log and errinfo plumbing | `util.cursor` `util.mem` `util.misc` `util.ctx` |
| `src/crypto/` | CRC-32C, SHA-256/384, HMAC, AES-128/192/256 + CBC, CTS, the primitive facade a host can override | `crypto.crc32c` `crypto.hash` `crypto.aes` `crypto.cts` `crypto.prim` `crypto.diff.ossl` |
| `src/denc/` | Ceph versioned envelopes, strings, blobs | `denc.envelope` |
| `src/msgr2/` | `entity_addr`, banner and preamble, the incremental receive parser, the transmit queue, control payloads (hello, auth, ident), pre-auth transcripts, the connection state machine | `denc.addr` `m2.frame` `m2.rx` `m2.replay` `m2.ctl` `m2.ctl.replay` `m2.preauth` `m2.conn.*` |
| `src/auth/` | `wr_key`, the cephx cipher and envelope, ticket parsing, the client machine, ticket renewal | `auth.key` `auth.cipher` `auth.client` `auth.client.err` `auth.renew` |
| `src/mon/` | monitor messages and `MonMap`, host list, hunting, subscriptions, raw map messages, renewal | `mon.msgs` `mon.hosts` `mon.client` `mon.session` |
| `src/client/` | the engine behind the public API: config profiles, memory layout, connection table, scheduler | `client.api` `client.mem` `client.pump` `client.secrets` `core.budgets` |

The test-only simulators (`harness/test/support/`: a scriptable msgr2 server and a fake monitor with a cephx server side) are checked by `sim.*`. The whole engine is fuzzed by `fuzz_client_session`.

## Rules (what the build checks)

- ISO C99, headers `<stddef.h>` and `<stdint.h>` only; no allocation, no global mutable state, no recursion, no floating point, no VLAs. Memory comes from the host in two regions (`arena`, `bulk`) at create; every length read from the wire is compared with a budget in `wr_config` first.
- Every `.c` file has a unique basename (iPXE derives object names from it). Files stay under about 500 lines (`core.docs` fails a file above 500). No recursion; the deepest direct call chain is 13 frames and the largest stack along any chain is about 1.5 KiB (gcc -O2 call graph, summed frame sizes), measured by `harness/tests/ci-docs-hardening/check_callgraph.py` in the CI job `static-limits`, which fails above 14 frames or 2 KiB. Calls through function pointers (host callbacks, the crypto override table) are not followed.
- `-Wall -Wextra -Werror` plus the long list in `harness/cmake/WrWarnings.cmake`, on gcc and clang, with and without `-DWR_SANITIZE=address,undefined`; `-Wframe-larger-than=1024`.
- Mechanical gates in ctest: `core_sources_in_sync`, `core_no_libc` (the library may reference only `memcpy/memmove/memset` and compiler arithmetic helpers; equality is `wri_ct_memeq`, so there is no `memcmp` and no `bcmp`), `core_no_globals` (no `.data`, `.bss`, COMMON or TLS), `core_freestanding`, `core_freestanding_os`, `core_freestanding_m32` (every core file compiled as ISO C99 with `-ffreestanding -nostdinc` and only the compiler's own `<stddef.h>` / `<stdint.h>`, then linked with `-nostdlib` next to a stub that defines `memcpy`, `memmove` and `memset` and nothing else: the link fails if the core needs any other symbol; this is what an iPXE or kernel build sees; `-O2`, `-Os` and 32-bit `-m32 -Os`), `core.budgets` (footprint of each profile, guard bands around the exactly sized regions, an oversized map message), `core.docs` (this file and `harness/README.md` against the tree: footprint table, file sizes, fuzz seeds, test names, licence tags, the CI workflow). The two object gates also run in CI on optimised builds (Release and MinSizeRel, gcc and clang) and on the 32-bit and iPXE-flag objects.
- Compiler note: the core never calls `memcmp` (it uses `wri_ct_memeq`), so clang at -O2 and above, which rewrites `memcmp(a, b, n) == 0` into a call to `bcmp`, has nothing to rewrite and the object code needs no flag. A host that overrides `WR_MEMCMP` is not affected either: nothing in the core uses it.
- Compile-only targets: `wr_core_m32` (32-bit `size_t` and pointers, as on i386 iPXE), `wr_core_ipxe_flags` (the iPXE build's own warning set, `-ffreestanding -Os`) and `wr_header_check` (each header compiles as the first include of a translation unit).

## Hardening review (Phase 1, milestone 10)

The whole core was reviewed once more as a unit, with tools as well as by reading. What was checked, and what came out:

| Area | How it was checked | Result |
|---|---|---|
| Memory safety | libFuzzer + ASan + UBSan on every decoder and on the whole engine; the minimised corpora replayed under MemorySanitizer (uninitialised reads) and the unit tests run under it; `scan-build`, `clang-tidy` (bugprone, cert, clang-analyzer), `cppcheck`, `gcc -fanalyzer` | no crash, no sanitizer report, no finding that survived reading (what the analyzers said: false positives about the "no memory only for the empty reader" invariant of `wri_rd` and about a `memset` the gcc analyzer cannot see through, and style notes about bounded products widened to `size_t` and one assignment in a condition) |
| Integer overflow and untrusted lengths | read every length use; `-fsanitize=unsigned-integer-overflow,implicit-conversion,local-bounds` over all unit tests and all fuzz corpora; the unit tests also built and run for 32 bits (`-m32`; there the footprint check of the documents and the position-independent-object gate are 64-bit and non-PIE by design) | every unsigned wrap reported is intended (hash and CRC arithmetic, the branch-free padding check, `0 - x` negation, sequence numbers that stop at the end of the range); no wire length is added to a position (`wri_rd` compares it with what is left), and the counts the decoders read go through `wri_rd_count` (a cap and a check against the remaining bytes) before a loop |
| Bounded memory | `core.budgets` (exact regions with guard bands), the work budget per pump step, `wri_rd_count` before every loop over wire counts | nothing allocates, every region is taken from the two host regions at create |
| Constant-time comparisons | read every comparison of a MAC, a signature, a ticket or a nonce | the cephx v2 MAC, the msgr2 signatures and the pre-auth digest go through `wri_ct_memeq`; the v1 padding check has no data-dependent branch; AES itself is table-driven and NOT constant time (stated in `wri_aes.c`; a host can override it through `wr_prim_ops`) |
| libc outside the shim | `core_no_libc` on the object code (Debug, Release, MinSizeRel, gcc, clang, 32-bit), `core_freestanding*` link | **fixed**: the core called `memcmp` in seven places, which clang at -O2 turns into `bcmp`, a symbol a kernel or iPXE build does not have (CI needed `-fno-builtin-memcmp` to hide it). All seven now use `wri_ct_memeq`; the library references `memcpy`, `memmove` and `memset` only |
| Global state | `core_no_globals` (no `.data`, `.bss`, COMMON, TLS) | clean |
| Error handling | `WR_MUST_CHECK` on every status-returning call under `-Werror`; every `(void)` cast in the core read | every ignored status is one whose error is recorded elsewhere (the reader or writer cursor) and said so in a comment |
| Licensing and copying | SPDX tag on every file (`core.docs`); a 4-line-window comparison of every core, test and harness file against the whole Ceph v20.2.5 source tree and the iPXE and WNBD submodules | the only matches are the `if (c >= 'A' && c <= 'Z')` digit ranges of a base64 decoder and `#include` lines; nothing copied |
| Freestanding suitability | `core_freestanding`, `core_freestanding_os`, `core_freestanding_m32`: ISO C99, `-ffreestanding -nostdinc`, only the compiler's own `<stddef.h>` and `<stdint.h>`, linked with `-nostdlib` against a stub with the three memory functions | gcc and clang, `-O0`/`-O2`/`-Os`, 64-bit and `-m32`: links |

Fuzzing, libFuzzer with ASan and UBSan, the core instrumented for coverage (`harness/tools/fuzz_long.sh` repeats it). Seeds: the committed vectors and the frames, control payloads, cephx replies and map messages cut out of the public captures. ## Memory footprint

`wr_client_mem_required()` returns the exact sizes of the two regions; the engine takes nothing after create. Measured by `harness/test/test_core_budgets.c` (which fails if a product profile exceeds its budget):

| Profile | arena | bulk | documented budget (arena / bulk) |
|---|---|---|---|
| `wr_config_profile_ipxe` | 106 KiB | 1030 KiB | 128 KiB / 1 MiB + 16 KiB |
| `wr_config_profile_kernel` | 462 KiB | 8198 KiB | 512 KiB / 8 MiB + 32 KiB |
| `wr_config_profile_harness` | 2.4 MiB | 32 MiB | (sanity cap 4 MiB / 40 MiB) |

The arena holds the hot state (connections, handshake transcripts, keys, tickets); the bulk holds the raw map message slots (`mon_msg_cap` each). The numbers are measured on a 64-bit host; the 32-bit iPXE build has smaller pointers, so its footprint is not larger. The test hands the engine regions of exactly the announced size inside guard bands, so a write past the end is a failure, and `core.docs` fails when this table drifts from the measured numbers. Details: `docs/design/core-architecture.md` section 5.

## Build and test

From a clean checkout, with gcc or clang (CMake 3.16 or newer; Ninja optional; OpenSSL development files, Python 3 and `gcc-multilib` are optional and make more tests run instead of skip):

```sh
cmake -S harness -B build && cmake --build build && ctest --test-dir build --output-on-failure
```

That is the whole check: 69 tests, of which 68 run anywhere. The one that needs the lab Ceph cluster (`lab.mon`, label `lab`, needs `WR_LAB_*` in the environment) skips by itself; `ctest -LE lab` leaves it out. [.github/workflows/core.yml](../.github/workflows/core.yml) runs exactly this with gcc and clang, Debug and Release, on `ubuntu-latest`; [.github/workflows/harness.yml](../.github/workflows/harness.yml) adds the sanitizer, 32-bit, iPXE-flag, call-depth and libFuzzer-smoke jobs. Warnings are errors in every one of them.

More in [harness/README.md](../harness/README.md) (options, one test, the sanitizers, long fuzz runs). In short: `cmake -S harness -B build/harness && cmake --build build/harness -j && ctest --test-dir build/harness --output-on-failure`. Design and implementation plan: [docs/design/core-architecture.md](../docs/design/core-architecture.md).
